Checks

Flow: the implicit flow (tokens in the URL) is flagged; the code flow with PKCE is the current recommendation for every client.

PKCE: S256 is required, plain is flagged, and you can paste the code_verifier to confirm it produces the code_challenge.

state and nonce: missing or short values are flagged. OIDC implicit and hybrid flows require a nonce.

redirect_uri: plain http outside loopback, and fragments, are flagged. A client_secret in a browser URL is treated as leaked.

Callbacks and errors

Error callbacks are explained in plain words: access_denied, invalid_scope, login_required and the rest. The iss parameter from RFC 9207, which protects against mix-up attacks, is recognised.

Questions

Is PKCE only for mobile apps?

No. It started there, but the OAuth 2.0 Security Best Current Practice recommends it for every client, including confidential server-side ones.

Are my tokens safe here?

The page makes no network requests and refresh tokens are never displayed. Prefer test or expired tokens anyway.
